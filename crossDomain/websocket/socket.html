1. 客户端发起 HTTP 升级请求（Client Request） 客户端发送一个标准的 HTTP 请求，但包含特殊的 WebSocket 升级头： http GET /chat HTTP/1.1 Host: example.com Upgrade: websocket // 协议升级为 WebSocket Connection: Upgrade // 要求切换协议 Sec-WebSocket-Key: dGhlIHNhbXBsZSBub25jZQ== // 随机生成的 16 字节 Base64 密钥 Sec-WebSocket-Version: 13 // 指定 WebSocket 协议版本（通常为 13） Origin: https://example.com // 安全验证（防跨域攻击） （可选其他头部，如认证信息等） 🔑 关键字段： Sec-WebSocket-Key：客户端生成的随机字符串（16 字节 Base64 编码），用于验证服务端是否支持 WebSocket。 Sec-WebSocket-Version：固定为 13（RFC 6455 标准版本）。 2. 服务端响应协议升级（Server Response） 服务端验证请求后，返回 HTTP 101 Switching Protocols 响应： http HTTP/1.1 101 Switching Protocols Upgrade: websocket Connection: Upgrade Sec-WebSocket-Accept: s3pPLMBiTxaQ9kYGzzhZRbK+xOo= // 客户端密钥计算后的结果 （可选其他头部，如设置 Cookie 等） 🔐 Sec-WebSocket-Accept 的生成逻辑： 拼接客户端传来的 Sec-WebSocket-Key（如 dGhlIHNhbXBsZSBub25jZQ==）与固定 GUID 258EAFA5-E914-47DA-95CA-C5AB0DC85B11。 对拼接后的字符串进行 SHA-1 哈希。 将哈希结果转换为 Base64 编码。 3. 连接升级完成 客户端验证 Sec-WebSocket-Accept 值正确后，底层 TCP 连接保持打开。 后续所有通信使用 WebSocket 二进制帧协议（非 HTTP），实现双向实时数据传输。
